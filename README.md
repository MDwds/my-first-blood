# 员工信息管理门户（Django）

一个包含员工端与管理员端的员工信息管理项目。员工只能查看和更新自己的资料；管理员可以搜索、录入、查看、修改、停用和删除员工账号。

## 已实现功能

- 员工登录入口与管理员登录入口分离，并按角色校验登录权限
- 员工个人主页：查看本人档案、资料完整度和账号状态
- 员工自助更新：仅允许修改电话、邮箱、地址、紧急联系人和个人简介
- 管理员控制台：员工总数、正常账号、部门数量、近 30 天新增统计
- 员工管理：新增、查看、修改、停用、删除
- 搜索与筛选：姓名、账号、电话、邮箱、职位、部门、账号状态
- 分页、表单校验、中文错误提示、CSRF 防护
- 管理员可为员工重置密码
- Django 原生后台入口：`/admin/`

## 快速启动

```powershell
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

访问：

- 员工登录：<http://127.0.0.1:8000/portal/login/>
- 管理员登录：<http://127.0.0.1:8000/portal/admin-login/>
- 员工管理：<http://127.0.0.1:8000/portal/manage/>
- Django 后台：<http://127.0.0.1:8000/admin/>

## 权限设计

| 操作 | 员工 | 管理员 |
| --- | --- | --- |
| 查看本人资料 | 允许 | 允许（通过管理列表） |
| 修改本人联系方式 | 允许 | 允许（通过员工编辑页） |
| 查看其他员工资料 | 禁止 | 允许 |
| 录入员工 | 禁止 | 允许 |
| 修改部门、职位、账号状态 | 禁止 | 允许 |
| 删除员工 | 禁止 | 允许 |

权限同时在视图层和查询层校验，不能只依赖隐藏页面按钮。

## 建议继续完善

1. **审计日志**：记录谁在何时修改或删除了哪个员工，便于追责与恢复。
2. **软删除**：删除时标记为离职而非直接移除，保留历史档案。
3. **部门数据权限**：为部门负责人增加“仅管理本部门员工”的范围权限。
4. **批量导入导出**：支持 Excel 模板导入、CSV 导出，并校验重复工号。
5. **密码自助找回**：接入企业邮箱或短信验证码。
6. **登录安全**：增加登录失败次数限制、验证码与可选双因素认证。
7. **组织架构**：增加部门表、岗位表和直属主管关系，替代自由文本字段。
8. **数据脱敏与备份**：手机号、紧急联系人按角色脱敏，并建立数据库备份策略。

## 上线前检查

- 将 `SECRET_KEY`、`DEBUG` 和 `ALLOWED_HOSTS` 改为环境变量配置
- 使用 PostgreSQL 或 MySQL，不建议生产环境继续使用 SQLite
- 配置 HTTPS、安全 Cookie、静态文件服务和日志
- 删除演示账号，并强制管理员使用高强度密码
- 增加员工隐私政策、数据保留周期和访问审计
